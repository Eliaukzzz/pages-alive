    它是怎么做到的？

    视频网站通过 Page Visibility API 判断你是否在看：切到别的标签页时， document.visibilityState 会变成 "hidden"，播放器收到 visibilitychange 后就把视频流降级成音频流，切回来时再重建解码器 —— 这就是卡顿的来源。

    这个扩展在该站点加载前就做了三件事：

    1. 把 document.hidden / visibilityState / hasFocus() 改成永远"可见、聚焦"；
    2. 在 window 捕获阶段吞掉 visibilitychange 与窗口 blur，页面根本收不到通知；
    3. 后台时用自己的定时器接管 requestAnimationFrame，并在标签页级别关闭自动丢弃。

    局限：浏览器底层的省电调度、页面在 Web Worker 里的检测、以及站点自己的服务端心跳无法被完全绕过； 极少数站点可能仍会降级。这个方案本质上是用一点后台 CPU 换流畅度，介意耗电可以关掉"保持动画帧"。
